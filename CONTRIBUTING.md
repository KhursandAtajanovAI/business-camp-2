# Contributing

Спасибо за вклад! Над проектом одновременно работают несколько людей и AI-агентов, поэтому правила строгие.

## Общие правила

- В `main` напрямую не пушим — только через Pull Request. Force-push запрещён.
- Никаких секретов, `.env`, персональных данных и дампов в репозитории (см. [SECURITY.md](SECURITY.md)).
- Перед коммитом проверьте `git diff --staged` на секреты.
- Коммиты — [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `chore:`.
- Один PR решает одну задачу и остаётся небольшим. PR мёржит владелец после проверки (squash-merge).
- Существенные архитектурные решения фиксируем как ADR в [`docs/decisions/`](docs/decisions/).

## Параллельная работа нескольких агентов

Идентификаторы: `cc1`, `cc2`, `cc3` (Claude Code), `cw1`, `cw2` (Cowork).

1. **Ветки:** `<агент>/<тип>/<кратко>`, тип — `feat`, `fix`, `docs`, `chore`. Пример: `cc2/feat/login-page`.
   Каждый агент работает в своей ветке и (локально) в своём `git worktree`.
2. **Взять задачу:** в [`TASKS.md`](TASKS.md) поставьте строке статус `in-progress` и свой идентификатор и закоммитьте эту отметку **первой**. Если строка уже занята — берите другую. Две одинаковые задачи брать нельзя.
3. **Актуальность:** перед работой и перед PR — `git fetch` и `git rebase origin/main`.
4. **Не трогайте** файлы, закреплённые за чужой задачей. Общие зоны (общие конфиги, lock-файлы, `TASKS.md`) правьте минимально и отдельным коммитом.
5. **Конфликты** разрешайте аккуратно, не теряя чужую работу. Не уверены — остановитесь и спросите владельца.
6. **Завершение:** откройте PR по шаблону, свяжите issue, поставьте строке в `TASKS.md` статус `review`.

## Pull Request

Заполните чек-лист в шаблоне: нет секретов, тесты пройдены, описание изменений, связанный issue. Все обсуждения в PR должны быть решены, CI — зелёный.
